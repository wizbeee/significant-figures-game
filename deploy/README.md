# 24시간 운영 가이드

교내 노트북을 계속 켜 두기 어려워, **영구 디스크가 딸린 무료 VM**에 올려 상시 운영하기 위한 문서입니다.

---

## 왜 이 구성인가

| 후보 | 판단 |
|---|---|
| **Oracle Cloud Always Free** | ✅ **채택.** 영구 디스크 있음, 항상 켜져 있음, 월 egress 넉넉함, 한국 리전(춘천·서울) 있음 |
| GCP e2-micro 무료 | ❌ 월 무료 egress가 1GB 수준. 이 앱은 폴링이 잦아 **수업 1회에 수백 MB** — 며칠이면 초과 |
| Render 무료 | ❌ 무료 플랜에 영구 디스크를 붙일 수 없음. 디스크가 없으면 재시작마다 학생 기록이 사라짐 |
| 학교 노트북 + 터널 | ❌ 노트북을 24시간 켜 둘 수 없다는 전제 |

부하는 문제가 아닙니다. 100명 동시 접속 = 약 83 req/s이고, `/api/state`는 메모리만 읽습니다.
응답 압축을 켠 뒤 전송량이 **약 80% 줄었습니다**(25명 방 기준 2974 → 601 bytes).

---

## 1. Oracle Cloud VM 만들기 (선생님이 직접 하셔야 하는 부분)

계정 생성에는 본인 확인과 카드 등록이 필요해서 대신 해 드릴 수 없습니다.

1. [cloud.oracle.com](https://cloud.oracle.com) 가입 — 리전은 **춘천(Chuncheon)** 또는 **서울(Seoul)** 선택
   - ⚠️ 리전은 나중에 못 바꿉니다.
2. **Compute → Instances → Create Instance**
   - Image: **Ubuntu 22.04** (또는 24.04)
   - Shape: **VM.Standard.A1.Flex** (ARM) — OCPU 1~2, 메모리 6~12GB면 충분
   - SSH 키: 브라우저에서 생성해 **개인키 파일을 반드시 내려받아 보관**
3. **VCN → 보안 목록 → 수신 규칙 추가**: `0.0.0.0/0` 에 대해 **TCP 80, 443**
   - 이 단계를 빠뜨려서 "접속이 안 된다"는 경우가 가장 많습니다.

> **A1.Flex가 "out of capacity"로 안 만들어질 수 있습니다.** 인기 리전에서 흔한 일입니다.
> 시간을 두고 재시도하거나, 성능이 낮은 무료 x86(VM.Standard.E2.1.Micro)으로도 이 앱은 충분히 돌아갑니다.

## 2. 도메인 (HTTPS용)

학생이 로그인하므로 HTTPS를 권합니다. 도메인이 없으면 [DuckDNS](https://duckdns.org) 같은
무료 서브도메인이면 충분합니다 (예: `sigfig.duckdns.org` → VM의 공인 IP로 연결).

## 3. 설치 — 명령 두 줄

> ✅ 공개 운영에 필요한 수정(`TRUST_PROXY`, gm3 정답 노출, 응답 압축, 명단 제한)은
> **2026-09-07 `main`에 병합 완료**되었습니다. 그냥 아래대로 설치하면 됩니다.


VM에 SSH로 접속한 뒤:

```bash
curl -fsSL https://raw.githubusercontent.com/wizbeee/significant-figures-game/main/deploy/setup-server.sh -o setup.sh
sudo bash setup.sh
```

도메인을 물어보면 입력하세요. 스크립트가 알아서 합니다:

- Node.js 20 설치
- 전용 계정(`sigfig`)으로 `/opt/sigfig`에 클론
- 데이터는 `/var/lib/sigfig` (권한 750 — 학생 개인정보가 있으므로 잠금)
- **systemd 등록** — 부팅 시 자동 실행, 죽으면 3초 후 재시작
- **Caddy 리버스 프록시** — HTTPS 인증서 자동 발급·자동 갱신
- **교사 비밀번호 자동 생성** (설치 마지막에 한 번 출력되니 옮겨 적으세요)
- 인스턴스 방화벽(ufw/iptables) 80·443 개방

Node 자체는 `127.0.0.1`에만 바인딩되어 **항상 Caddy를 거칩니다.**

## 4. 설치 후 반드시 할 것

1. **교사 화면 로그인** → 자동 생성된 비밀번호 사용
2. **명단 등록 + "명단 학생만 입장" 켜기**
   인터넷에 공개되므로, 이걸 켜지 않으면 아무나 아무 학번으로 들어올 수 있습니다.
3. 시즌 설정 확인 (점심·저녁 운영 창)

## 운영

```bash
sudo systemctl status sigfig      # 상태
sudo journalctl -u sigfig -f      # 실시간 로그
sudo systemctl restart sigfig     # 재시작
sudo bash setup.sh                # 최신 코드로 갱신 (다시 실행해도 안전)
```

**백업** — `/var/lib/sigfig` 하나만 받으면 됩니다.

```bash
sudo tar czf ~/sigfig-backup-$(date +%F).tar.gz -C /var/lib sigfig
```

교사 화면의 내보내기 기능도 함께 쓰면 더 안전합니다.

## 공개 운영 시 보안 설정

설치 스크립트가 아래를 자동으로 잡아 줍니다. 직접 구성한다면 확인하세요.

| 항목 | 값 | 이유 |
|---|---|---|
| `TEACHER_PASSWORD` | 20자 무작위 | **기본값이 `3000`(4자리)** 입니다. 그대로 공개하면 금방 뚫립니다 |
| `TRUST_PROXY` | `1` (프록시 뒤일 때만) | `x-forwarded-for`는 위조 가능. 프록시가 없는데 신뢰하면 레이트리밋이 무력화됩니다 |
| `CORS_ORIGIN` | 실제 도메인 | 기본값 `*`는 아무 사이트나 API를 부를 수 있음 |
| `HOST` | `127.0.0.1` | Node를 직접 노출하지 않고 Caddy 뒤에 둠 |

### 남아 있는 한계 (알고 쓰셔야 하는 부분)

- **학생 로그인은 학번 + 이름뿐이고 비밀번호가 없습니다.** 명단 제한을 켜도
  같은 반 학생끼리 서로를 사칭할 수 있습니다. 교내 LAN에서는 사실상 문제가 없었지만,
  인터넷에 열면 이야기가 다릅니다.
  → **발주자 결정(2026-09-07): 일단 명단 제한만으로 운영.** 연습·복습 용도라는 전제입니다.
  **이 서버의 점수·출결을 성적에 직접 반영하려면** 학생별 비밀번호가 먼저 필요하며,
  그때는 별도 작업으로 요청하세요.
- **측정값 읽기(gm3) 모드는 기구를 그리는 데 필요한 값이 클라이언트로 갑니다.**
  정답(유효숫자 개수)은 더 이상 보내지 않지만, 개발자도구로 원래 값을 볼 수는 있습니다.
  평가용으로 쓴다면 이 점을 감안하세요.
